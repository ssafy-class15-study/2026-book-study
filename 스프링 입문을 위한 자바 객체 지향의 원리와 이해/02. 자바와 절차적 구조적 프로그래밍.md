자바는 객체 지향 언어. 근본적으로 프로그래밍 언어.

### 자바 프로그램의 개발과 구동

자바는 내부의 가상 세계에서 현실 세계의 물리적 컴퓨터인 `하드웨어`, 하드웨어가 구동시키는 `운영체제`, 그 위에서 구동될 `소프트웨어` 를 모방한다.

| 현실 세계 | 가상 세계 |
| --- | --- |
| 물리적 컴퓨터 - 하드웨어 | `JVM` - 자바 가상 기계 : 가상 컴퓨터 |
| 운영체제 | `JRE` - 자바 실행 환경 : JVM용 OS |
| 소프트웨어(SW) 개발 도구 | `JDK` - 자바 개발 도구 : JVM용 SW 개발 도구 |

> `JVM` ⊂ `JRE` ⊂ `JDK`
> 

JDK에는 javac.exe가 포함되어 있음 : `javac` 자바 소스 컴파일러

JRE에는 java.exe가 포함되어 있음 : `java` 자바 실행기

JRE는 프로그램 내부에 main 메서드를 탐색. main 메서드가 확인 되면, JVM을 부팅시킨다.

- 왜 이런 구조로 되어있는지 설명 가능하면 좋다. (`WORA`)
    - WORA
        
        Write Once Run Anywhere
        
        기존의 C, C++은 각 OS마다 메모리 구조, 시스템 호출 방식 등이 달라서 소스코드가 각자 달라야 하지만, 
        
        Java의 경우 .class 파일로 컴파일만 하면, 각 OS별로 JRE만 들고 있으면 구동 가능.
        

모든 프로그래밍 언어는 프로그램이 실행될 때, 메모리 영역을 `코드 실행 영역` ↔ `데이터 저장 영역`

객체 지향 프로그램에서는 `데이터 저장 영역`을 다시 3개의 영역으로 나눈다.

`스태틱 영역`, `스택 영역`, `힙 영역`

`코드 실행 영역` 은 컴퓨터 작동 원리를 이해하는 데에 도움 되지만, 우리는 `데이터 저장 영역`의 삼분할 구조만 살펴보자. 

### 자바에 존재하는 절차적/구조적 프로그래밍의 유산

객체 지향 프로그래밍이 있기 전에, 절차적 프로그래밍이 존재했다.

절차적 프로그래밍 시절에는 개발자들의 실수를 유도하는 치명적인 키워드 `goto` 가 존재한다.

제임스 고슬링은 이 키워드로 고역을 치른 적이 있는 지, `goto` 자체를 사용하지 못하도록 예약어로 등록해놨다.

또, 객체 지향 프로그래밍이 있기 전에, 구조적 프로그래밍이 존재했다.

구조적 프로그래밍은 `함수`를 사용하여 중복 코드를 한 곳에서 관리하고 논리를 통해 이해하기 쉬운 코드를 작성할 수 있다.

> 구조적 프로그래밍의 지침 : 공유 사용 시, 문제 발생이 높은 전역 변수보다는 지역 변수를 쓰자
> 

객체 지향 언어(자바)에서는 절차적/구조적 프로그래밍의 유산은 메서드에서 확인 가능하다. 

→ 클래스 내부엔 변수 선언이나 메서드 정의만 가능하다.

- 메서드 내부에만 제어문이 존재할 수 있다.
- goto를 없애고 if-else, switch, while, for과 같은 제어문이 대체.
- 함수라는 단어 대신 클래스 내부에 정의된다고 그냥 `메서드`로 부르기로 했다.

### 데이터 저장 영역 - (Static, Stack) Heap은 3장부터 설명

JRE가 부팅시킨 JVM은 .class 파일(목적파일)을 뒤지면서 전처리 과정을 하는데, 이 때 Static 영역에 필요한 정보들을 넣는다.

> Static 영역 : **클래스들의 놀이터**
> 

전처리 로딩

- java.lang 패키지
- main 메서드를 포함한 클래스(변수명, 변수타입, 접근제어자, static 변수)

lazy 로딩 (쓰겠다고 할 때부터 로딩)

- import하는 패키지들의 클래스

<aside>
💡

전역변수의 남발이 좋지 않은 이유?

---

Static 영역에 올라간 static 변수는 클래스가 로딩되면, 클래스가 사라질 때까지 존재. (메모리 차지)

Stack 영역의 변수는 메서드가 사라지면 없어지고, Heap 영역은 아무도 참조하지 않으면 GC가 수거.

</aside>

> Stack 영역 : **메서드들의 놀이터**
> 
- 메서드를 호출해, 여는 중괄호를 만날때마다 스택 프레임이 스택 영역에 생성.
    - 스택 프레임에는 메서드의 인자, 지역 변수, 리턴 값이 생성
    - 스택 프레임 내의 지역 변수에는 쓰레기값이 들어있어, 초기화가 필요하다.
    - 스택 프레임 내부에서 다시 여는 중괄호를 만날 시, 해당 블록 내부에서 스택프레임이 생성, 내부에서는 외부 접근 가능하지만, 역은 불가능
- 서로 다른 스택 프레임의 지역 변수에는 당연히 접근 불가능하다. (내부에서 외부 접근 이런 거 없음. 편의를 위해)
    - Call by Value를 이용해 리턴값을 통해 값을 복제해서 전달하면 메서드끼리 값을 전달 가능하다.
- main메서드를 닫게되면 데이터 저장 영역 소멸, JVM 가동 정지, JRE이 시스템 자원을 운영체제에 반납하게 된다.

### 전역 변수 쓰지 마세요

위에서는 전역 변수의 단점이 메모리 차지라고 말했지만, 전역 변수의 수정이 일어났을 때, 값의 변화가 일어난 이유를 찾기 위해서는 수천, 수만 줄을 뒤져야만 판단이 가능할 수 있다.

전역 상수(static final)가 아니면, 지양하자.

### 멀티 스레드 / 멀티 프로세스

`멀티 프로세스`는 다수의 데이터 저장 영역(T메모리) 를 가진다.

- 각 프로세스마다 고유의 공간으로 침범할 수 없다.

`멀티 스레드`는 하나의 T메모리 안에서 스택 영역을 스레드 개수만큼 분할한다.

- 그만큼 효율적이다.
- 각 스레드마다 다른 스레드의 힙, 스태틱 영역을 공유하며 가진다.

Java Servlet은 요청당 스레드를 생성한다.

멀티 스레드에서 쓰기 가능한 전역 변수를 사용시, 여러 요청이 동시에 해당 전역 변수에 쓰기/읽기를 하게 되면, 값의 일관성과 무결성이 깨지게 된다.
