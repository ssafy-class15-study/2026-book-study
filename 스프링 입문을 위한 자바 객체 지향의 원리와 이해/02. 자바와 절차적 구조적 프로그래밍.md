## 자바에 존재하는 절차적/구조적 프로그래밍의 유산

- 객체 지향 프로그래밍이락 해서 절차적,구조적 프로그래밍과 완전 무관하다고 볼 수는 없고 어느정도 객체 지향 언어에 녹아 있음
- 절차적 프로그래밍을 한 마디로 표현하자면 **`goto`** 를 쓰지 말라는 것.

<img width="640" height="259" alt="image 3" src="https://github.com/user-attachments/assets/38ef8ac4-be58-441c-9005-abf1215916e4" />


- 여기서 goto, const가 존재하는 것을 알 수 있음 → 사용하기 위해 등록해 놓은 것이 아니라 쓰지 말라고 선점을 해놓은 것
- const는 자바에서는 final이 대신하기 때문에 들어있음
- goto를 왜 사용하지 못하게 했냐면 프로그램의 실행 순서가 이리저리 이동하게 되면 소스를 이해하기에 굉장히 어려워지기 때문. → **goto를 이용한 이동은 프로그램을 논리적으로 잘 구성하면 모두 피할 수 있음**
- 구조적 프로그래밍 → 함수를 사용하라는 것
    - 함수의 장점 : **중복 코드 관리 가능, 논리를 함수 단위로 분해해 이해하기 쉬운 코드 작성**
    - 구조적 프로그래밍의 지침 : **공유 사용 시 문제가 발생하기 쉬운 전역 변수 보다는 지역 변수 사용을 권장**
- 자바에서의 절차적,구조적 프로그래밍의 유산은 메서드 안에서 확인할 수 있다.
    - 객체 지향 언어에서 제어문이 **존재할 수 있는 유일한 공간은 메서드 내부이기 때문이다.**

### 함수와 메서드는 뭐가 다르나요

- 결론은 다르지 않음
    - 굳이 차이점을 찾는다면 함수는 클래스, 객체와 관계가 없지만.. **메서드는 반드시 클래스 정의 안에 존재해야 한다는 것**

## T 메모리 구조

- Static 영역 : 클래스
- Stack 영역 : 메서드들의 놀이터
- Heap 영역 : 객체들의 놀이터

### Static 영역(클래스)

- 무엇이 저장되나 : 클래스 정보(멤버 이름, 데이터 타입, 접근 제어자), `static` 변수, 패키지 정보
- 생명주기 : JVM이 시작되고 클래스가 처음 사용될때, 프로그램이 종료될때
- 특징 : 어디서든 접근 가능한 **전역 변수**의 특징을 가짐(그렇지만 전역 변수 사용은 지향하자)

### Stack 영역(메서드)

- 무엇이 저장되나 : 메서드의 실행 프레임, 지역 변수, 매개변수, 리턴 값
- 작동 방식 : 메서드 호출 시 프레임이 생기면서(Push), 끝나면 사라짐 (pop) → main() 포함
    - 닫는 중괄호 ‘}’를 만나면 해당 스코프의 스택 프레임이 사라짐
- 특징 : 외부 스택 프레임에서는 내부 스택 프레임의 변수에 접근할 수 없지만, 내부에서는 가능(스코프 규칙

### Heap 영역(객체 영역)

- 무엇이 저장되나 : `new` 로 생성된 객체와 그 인스턴스 변수
- 특징 : 스택 영역 변수가 힙 영역의 객체 주소값을 가지고 참조, 더 이상 참조하지 않는다면 **가비지 컬렉터**가 자동으로 수거
    
    
    | **변수 종류** | **선언 위치** | **저장되는 메모리 영역** | **생명 주기 (Life Cycle)** |
    | --- | --- | --- | --- |
    | **지역 변수** (Local Variable) | 메서드 내부 | **Stack** 영역 | 메서드(또는 블록)가 실행되는 동안만 존재 |
    | **인스턴스 변수** (Member Variable) | 클래스 내부 (static 없음) | **Heap** 영역 | 객체가 생성될 때 ~ 객체가 GC에 의해 사라질 때 |
    | **클래스 변수** (Static Variable) | 클래스 내부 (static 있음) | **Static** 영역 | 프로그램 시작(클래스 로딩) ~ 프로그램 종료 |

## 멀티 스레드/ 멀티 프로세스

### 멀티 스레드

- 하나의 T 메모리안에 스택 영역을 스레드 갯수만큼 분할해서 사용하는 것
    - **Static, Heap 영역 모든 스레드가 공유**!
- 특징 :  Static, Heap 영역을 공유하므로 메모리를 절약할 수 있음
    - 위험성 : 앞서 말한 공유 영역에 있는 변수를 여러 스레드가 동시에 건드라면 **값이 꼬이는 심각한 버그** 발생

### 멀티 프로세스

- 각 프로세스가 마다 **고유한 T 메모리를 독립적으로 가짐**
- 특징 : 한 프로세스가 오류로 죽어도 다른 프로세스에는 영향을 주지 않으나, 똑같은 클래스 정보 (Static) 등을 중복해서 로딩하므로 메모리 사용량이 큼

| **구분** | **T 메모리 구조** | **변수 공유 여부** | **안정성 및 특징** |
| --- | --- | --- | --- |
| **멀티 프로세스** | 프로세스마다 T 메모리 **전체 생성** | 공유 **X** (완전 독립) | 안전하지만 메모리 사용량 많음 |
| **멀티 스레드** | **하나의 T 메모리** 사용 | **Static/Heap 공유**, Stack만 독립 | 메모리 효율적, **동기화 문제 주의 필요** |
