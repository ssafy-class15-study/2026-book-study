# 02. 자바와 절차적/ 구조적 프로그래밍

2장의 주제: 프로그래밍 언어로서의 자바를 다시 살펴보는 것

- 변수가 메모리에 어떻게 저장되고 사용되는지, 메서드가 어떻게 호출되고 메모리에 어떤 변화를 일으키는지 살펴본다.
- 이는 객체 지향 프로그래밍과 스프링으로 나아가기 위한 사진 지식


| 현실세계 | 가상세계 |
| --- | --- |
| 소프트웨어 개발 도구 | JDK(Java Development Kit) - 자바 개발 도구  |
| OS | JRE (Java Runtime Environment)- 자바 실행 환경  |
| 하드웨어 | JVM (Java Virtual Machine)- 자바 가상 머신 |

JDK에 의해 개발된 프로그램이 JRE에 의해 JVM 상에서 구동된다.

JDK는 자바 소스 컴파일러인 javac.exe를 포함

JRE는 자바 프로그램 실행기인 java.exe를 포함

JVM은 OS 플랫폼으로부터 독립적으로 프로그램을 구동시켜준다.

### 자바에 존재하는 절차적/구조적 프로그래밍의 유산

자바가 객체 지향 프로그래밍이라고 하지만, 프로그래밍의 유산인 절차적/ 구조적 프로그램의 어깨를 딛고 있다.

`goto` 명령어를 쓰지 말 것 - 절차적 프로그래밍 -

- 절차적 프로그래밍을 한마디로 표현하면 `goto` 명령어를 사용하지 않는 것인데, goto를 사용하면 프로그램의 실행 순서를 이리저리 이동할 수 있게 된다.
- 이러면 소스를 이리저리 따라가면서 프로그램을 이해해야해서 이해하기가 어렵다.(스파게티 코드를 방지하는 것)

`함수`를 사용하라 -구조적 프로그래밍-

- 함수를 사용하는건 중복 코드를 한 곳에 모을 수 있기 때문
- 논리를 함수 단위로 분리해서 이해하기 쉬운 코드를 작성할 수 있기 때문
- 또한 공유 사용 시 문제가 발생하기 쉬운 전역 변수보다는 지역 변수를 쓸 것

⇒ 이런 절차적, 구조걱 프로그래밍의 유산은 자바의 `메서드`  안에서 확인할 수 있다.

- 함수와 메서드는 거의 비슷한 의미지만, 함수는 클래스나 객체와 관계 없지만 메서드는 클래스 안에서만 정의 가능하다.
- 메서드 안에서는 반복문, 조건문이 존재하고 이것이 절차적, 구조적 프로그래밍의 흔적

### 메서드 스택 프레임

자바의 데이터 저장 영역은 스태틱(메서드), 스택, 힙 영역으로 이루어져 있는데 이를 책에서는 T자형 메모리 구조라고 말한다.

자바 프로그래밍의 동작 순서

- JRE는 먼저 프로그램 안에 main() 메서드가 있는지 확인한다.
- main 메서드가 확인되면 JVM을 가동시킨다. JVM은 JRE에 의해 전달 받은 파일을 실행시키는데, 가장 먼저 ‘전처리’라는 과정을 수행한다. JVM은 자바 프로그램을 실행시키 위한 메모리 구조를 만든다.
- 이후  `java.lang` 패키지를 스태틱 영역에 업로드한다. 이후 개발자가 작성한 모든 클래스와 import 패키지를 스태틱 영역에 가져다 놓는다.
- 이제 main 메서드가 실행되면 이를 스택 영역에 할당하는데 이때 메서드마다 스택 프레임을 생성한다. 스택 영역은 클래스의 중괄호를 제외한 중괄호를 만났을 때 생성된다.
    - 정확히 말하면 실행 컨텍스트를 만나면 스택 프레임을 생성하고
    - 대표적으로 메서드 호출, 생성자 호출, 초기화 블록 실행이 있다.
    - 그런데 초기화 블록 코드는 JVM 내부적으로 컴파일 시 생성자 안으로 합쳐지게 된다. 그래서 생성자 호출이 수행되는 스택 프레임 안에서 실행되게 된다.
- 스택 영역은 메서드가 종료되면 사라지만 힙, 메서드 영역은 main 메서드가 종료됐다고 사라지지 않는다. JVM은 main 메서드를 프로그램의 전체라고 생각하지 않기 때문인데, 다른 스레드나 데몬 스레드, 서버 등이 존재할 수 있기 때문이다.

```json
// 전체 생명 주기 
JVM 시작
 ├─ 메서드 영역 생성
 ├─ 힙 생성
 ├─ 스택 생성 (main)
 │    ├─ 메서드 호출 → 스택 프레임 생성/제거
 │
main 종료
 │
(다른 스레드 있으면 계속 실행)
 │
JVM 종료
 ├─ 스택 제거
 ├─ 힙 제거
 └─ 메서드 영역 제거
```

### 변수와 메모리

우리는 메서드나 클래스 내부에 지역 변수나 인스턴스 변수를 자주 선언하는데 JVM 메모리 구조에서 이는 어떻게 저장될까?

```java
int num = 10; 
```

우리는 이렇게 자주 변수를 선언하지만 사실 이 명령어는 변수 선언과 초기화라는 두 가지 명령어를 하나로 합친 것이다.

지역 변수가 선언될 때 해당 메서드 내부에 이 변수를 담기 위한 저장 공간을 마련해둔다. 그리고 변수가 초기화 될 때 이 저장 공간에 값을 저장한다. 지역 변수들은 선언된 메서드가 종료될 때 스택 프레임과 함께 사라진다.

변수는 지역 변수 이외에도 클래스 멤버 변수, 객체 멤버 변수가 존재하는데 JVM 메모리 영역마다 하나씩 존재한다.

지역 변수 → 스택 영역(정확히는 선언된 스택 프레임)

클래스 멤버 변수 → 스태틱 영역 (JVM이 종료될 때 까지 존재함)

객체 멤버 변수 → 힙 영역 (가비지 컬렉터에 의해 회수될 때 까지 존재함)

외부 스택 프레임에서 내부 스택 프레임 변수에 접근하는 것은 불가능하지만 그 반대는 가능하다. (한 메서드 내부에서)

⇒ 내부 스택 프레임은 외부 스텍 프레임의 변수들의 정보를 알고 있지만 외부 스텍 프레임의 변수들은 내부 스텍 프레임의 정보를 알 수가 없다.

그런데 메서드 안에서 메서드가 또 실행되기도 하는데 이럴 때 메서드 스택 프레임은 스택 영역 안에 스택 자료구조처럼 위로 쌓이게 된다.

⇒ 이 때는 서로의 지역변수에 접근이 불가능하다. 전역 변수끼리는 접근이 가능하고, 인자와 반환 값을 통해서만 값을 전달할 수 있다. 여기서 중요한 부분이 있는데 자바는 값을 복사한다는 것이다.

- 이렇게 입력값들과 반환 값에 의해서만 메서드 사이에 값이 전달될 뿐 서로 내부의 지역 변수를 볼 수 없다는 걸 메서드를 블랙박스화 한다고 한다.

메서드끼리 서로 지역 변수를 공유할 수 없는 이유는 무엇일까?

1. 메서드는 서로의 고유한 공간이기 때문
2. 또한 지역 변수도 주소 값을 가지고 있는 변수인데 이를 사용하려면 해당 주소값의 위치를 명확히 알아야하는데 자바에는 포인터가 없다.
3. 메서드는 다양한 곳에서 호출되는데 그 때마다 지역 변수의 값이 바뀌게 되면 메서드에서 의도한 결과를 가져오지 못할 수 있다.

책에서는 전역 변수를 되도록 사용하지 않고, 사용한다면 `final` 키워드를 붙여 전역 상수화해 사용하는 것을 권장한다.

전역 변수 사용을 지양하는 이유는 여러 메서드에서 전역 변수의 값에 접근하게 되면 결국 어떤 값이 저장되어 있는지 알기 어렵기 때문이다.

### 멀티 스레드/ 멀티 프로세스

멀티 프로세스는 각 프로세스 마다 각자의 T 메모리가 있고 각자 고유의 공간이므로 서로 참조할 수 없지만 멀티 스레드 환경에서는 하나의 T 메모리를 사용하되 스택 영역만 분할해서 사용한다.

- 힙과 메서드 영역은 스레드간 공유해야 할 데이터지만, 스택은 스레드의 실행 흐름 그 자체라고 볼 수 있다. 스레드 생성시 스택도 같이 생성되고, 스레드 종료시 스택도 같이 제거된다.
    - StackOverflowError는 **스레드 단위**
    - OutOfMemoryError는 **JVM 단위**

서블릿은 요청당 프로세스를 생성하는 것이 아닌 스레드를 생성한다.

- 지역 변수는 thread-safe (스레드끼리 독립적으로 사용)
- static / 인스턴스 변수는 thread-unsafe (스레드가 공유하며 사용)
