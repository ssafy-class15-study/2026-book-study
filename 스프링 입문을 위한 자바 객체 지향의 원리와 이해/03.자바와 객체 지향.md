# 03. 자바와 객체 지향

우리가 눈으로 보고, 느끼고, 생활하는 현실 세계처럼 프로그래밍 할 수 없을가? → 객체 지향의 탄생 

- 기존 구조적 프로그래밍 언어에서 중요한 것은 함수 (문제를 논리적 단위인 함수로 분할해 정복하자)

<aside>

세상에 존재하는 모든 것으 사물, 즉 객체이다

각각의 사물은 고유하다 → class 

사물은 속성을 갖는다 → property

사물은 행위를 한다  → moethod 

</aside>

- 객체 지향의 등장으로 속성과 행위를 한 곳에 묶어두기 시작했다.


> 클래스와 객체를 어떻게 구별할 수 있을까?
> 
> 
> : 그것의 속성 값 을 물어봤을 때 답할 수 있다면 객체이다. 반대로 답할 수 없다면 클래스이다.
> 

객체 지향의 4가지 특성

- 캡슐화
- 상속 : 재사용 + 확장
- 추상화(Abastraction) : 모델링
- 다형성

### 추상화

**추상: 여러가지 사물이나 개념에서 공통되는 특성이나 속성 따위를 추출하여 파악하는 작용** 

⇒ 객체지향의 추상화는 ‘모델링’이다.

- 즉, 구체적인 것을 분해해서 관찰자가 관심 있는 특성만 가지고 재조합하는 것.
- 구체적인 것을 분해해서 관심 영역(애플리케이션 경계)에 있는 특성만 가지고 재조합 하는 것 = 모델링)

객체: 세상에 존재하는 유일 무이한 사물 

클래스: 분류, 집합 같은 속성과 기능을 가진 객체를 총칭하는 개념

```java
사람 홍길동 = new 사람(); 
```

그런데 사물을 추상화 해 모델링한 것이 객체라고 한다면 어떤 부분을 추상화해야할까?

⇒ 내가 만들고자 하는 애플리케이션이 어디에서 사용될 것인가? 

- 즉 애플리케이션 경계에 따라 클래스의 설계가 달라지게 된다.
- 추상화는 주관적이고, 도메인 지식이 여기서 나온다고 생각함

자바는 객체 지향의 추상화를 class 키워드를 통해 지원하고 있다

- 추상화 = 모델링 = 자바의 class 키워드

- 새로운 객체를 하나 생성해 그 객체의 주소 값을 객체 참조 변수에 할당한다

클래스 변수와 멤버 변수의 차이점 

: 클래스 변수(정적 속성)은 해당 클래스의 모든 객체가 같은 값을 가질 때 사용하는 것이 기본이다. (그래서 전역 상수로 자주 사용한다)

- 클래스 변수는 스태틱 영역에 클래스가 배치될 때 클래스 내부에 메모리 공간이 확보된다.
- 멤버 변수는 객체가 생성될 때 그 때 힙 영역의 객체 인스턴스 안에 메모리 공간이 할당된다.

| 이름 | 다른 이름 | 메모리 공간 |
| --- | --- | --- |
| static 변수 | 클래스 속성(변수), 정적 변수, 정적 속성 | 스태틱 영역 |
| 인스턴스 변수  | 객체 속성, 객체 변수, 멤버 변수  | 힙 영역 |
| local 변수 | 지역 변수 | 스택 영역(스택 프레임 내부) |

### 상속 : 재사용 + 확장

객체 지향에서 상속은 상위 클래스의 특성을 하위 클래스에서 상속(특성 상속)하고 거기에 더해 필요한 특성을 추가, 즉 확장해서 사용할 수 있다는 의미이다. 

- 클래스의 특성을 상속하는 것이지, 클래스를 상속하는 것이 아니다.
- 그래서 super - sub의 관계가 맞다

⇒ 상속을 하며 특성이 확장되는 것이지 계층적인 구조가 아니다. 

따라서 `{하위 클래스}는 {상위 클래스}다.` 라는 말이 말이 되어야 한다.

- 아버지는 할아버지다 ⇒ x
- 포유류는 동물이다 ⇒ o
- 고래는 포유류이다 ⇒ o
- 고래는 동물이다  ⇒ o

→ 상속 관계는 `is a` 관계보다 `is a kind of` 관계로 표현하는게 더 적절하다.

TIP) 클래스 명은 분류스럽게, 객체 참조 변수명은 유일무이한 사물처럼 작성하는게 좋다. 

<aside>

객체 지향의 상속은 상위 클래스의 특성을 재사용하는 것이다.

객체 지향의 상속은 상위 클래스의 특성을 확장하는 것이다.

객체 지향의 상속은 is a kind of 관계를 만족해야 한다. 

</aside>

- **하위 클래스의 인스턴스가 생성될 때 상위 클래스의 인스턴스도 함께 생성된다. (중요)**

참고로 인터페이스는 구현 클래스와 `is able to` 관계를 갖고 있다.

구현 클래스 `is able to` 인터페이스 (인터페이스는 ~able 식의 이름이 많다)

재사용 되는 특성은 많을 수록 좋고, 구현해야할 속성은 적을 수록 좋다. 

### 다형성: 사용 편의성

객체 지향에서 다형성은

- 오버로딩과 오버라이딩
- 인터페이스와 구현 클래스

이렇게 두 가지가 존재한다. 

오버로딩은 같은 메서드 이름, 다른 인자 목록으로 다수의 메서드를 중복 정의한 것을 의미한다. 

- 인자 타입만 다른 메서드를 추가로 계속 중복 정의할 수 있어 편하다.

오버라이딩은 상위 클래스의 메서드를 재정의한 것이다

- 클래스가 하위 클래스일 때 상위 클래스 타입의 객체 참조 변수를 사용하더라도 하위 클래스에서 오버라이딩한 메서드가 호출된다.

``` java
    Animal pingu = new Pengiun();
    pingu.showName();
```

오버라딩 또한 하위 클래스가 재정의한 메서드를 알아서 호출해줌으로써 형변환이나 하위 클래스가 무엇인지 신경 쓰지 않아도 되게 해준다.

### 캡슐화: 정보 은닉

`+`public - 모두가 접근 가능

`#`protected - 상속, 패키지 

`~`default - 패키지

`-`  private - 본인만 가능 

상속을 받지 않았다면 객체 멤버는 객체를 생성한 후 객체 참조 변수를 이용해 접근해야 한다.

정적 멤버는 클래스명.정적멤버 형식으로 접근하는 것을 권장한다.

- 일관된 형식으로 접근하기 위함이다

### 참조 변수의 복사

기본 자료형 변수는 저장하고 있는 그 값 자체로 해석 → Call By Value

객체 참조 변수는 저장하고 있는 주소로 해석 → Call By Reference

⇒ 사실 본질적으로는 이 둘이 차이가 없음 

- 객체 참조 변수가 가진 값 자체가 주소 값이라서 그걸 복사해 넘겨주는 것이기 때문
