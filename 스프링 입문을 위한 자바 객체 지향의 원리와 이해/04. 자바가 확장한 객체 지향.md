# 04. 자바가 확장한 객체 지향

이번 장에선 자바가 객체 지향을 확장하기 위해 사용하는 키워드와 개념 정리

## abstract 키워드 - 추상 메서드와 추상 클래스

- 선언부가 있는데, 구현부가 없는 **메서드**
- 추상 메서드를 하나라도 가지고 있는 **클래스**는 반드시 추상 클래스로 선언해야 한다.
- 추상 메서드 없이도 추상 클래스를 선언하는 것이 가능하다.

<aside>
💡

선언부만 있는 메서드를 어떨 때 사용하는가?

---

```cpp
public abstract class Animal {
	abstract void sound();
}
```

```java
public class AnimalTest {
	public static void main(String[] args) {
		Animal[] animalList = new Animal[3];
		
		animalList[0] = new Rat();
		animalList[1] = new Cat();
		animalList[2] = new Horse();
		
		for(int i = 0; i < 3; ++i) {
			animalList[i].sound();
		}
	}
}
```

다형성을 통해 Animal 타입의 참조 변수를 하위 클래스의 인스턴스 메서드인 sound()를 호출하고 있으니 상위 클래스에 sound() 메서드는 반드시 존재해야 한다. (하위 클래스에는 abstract 메서드가 아니라면 선택적으로 overriding 해도 되긴 함)

정작 동물 자체는 어떻게 울어야하는 걸까? 

실수로 동물 클래스의 인스턴스를 만들고 sound()를 호출하면 난감해진다.

추상 메서드와 추상 클래스는 이 문제를 한 번에 해결한다.

- 추상 클래스는 인스턴스를 만들 수 없다.
- 추상 메서드는 하위 클래스에게 메서드의 구현 (오버라이딩)을 강제한다.
- 추상 메서드를 포함하는 클래스는 반드시 추상 클래스이다.
</aside>

## 생성자

- 개발자가 아무런 생성자도 만들지 않으면, 자바는 인자가 없는 기본 생성자를 자동으로 만들어준다.
- 인자가 있는 생성자를 하나라도 만든다면, 자바는 기본 생성자를 만들어 주지 않는다.

생성자는 개발자가 필요한 만큼 오버로딩해서 만들 수 있다.

생성자는 정확하게 표현하자면 **객체 생성자 메서드**!

## 클래스 생성 시의 실행 블록, static 블록

객체 생성자가 있다면, 클래스 생성자도 있을 거라고 생각할 수 있다.

클래스 생성자는 존재하지도 않는다.

but, 클래스가 스태틱 영역에 배치될 때, 실행되는 코드 블록이 있다.

```java
// static 블록
public class 동물 {
	static {
		System.out.println("동물 클래스 로드");
	}
}	
```

static 블록에서 사용할 수 있는 속성과 메서드는 당연히 static 메버 뿐이다. (객체 멤버는 객체 생성자를 통해 heap 영역에 생성, 클래스 멤버는 클래스가 생성될 때 static 영역에 생성)

클래스 정보는  해당 클래스가 코드에서 맨 처음 사용될 때 T 메모리의 스태틱 영역에 lazy loading 된다.! static블록은 이 때, 단 한 번 실행된다.

<aside>
💡

클래스가 맨 처음 사용될 때?

---

- 클래스의 정적 속성을 사용할 때
- 클래스의 정적 메서드를 사용할 때
- 클래스의 인스턴스를 최초로 만들 때
</aside>

스태틱 영역도 메모리이기 때문에, 최대한 늦게 사용을 시작하기 위해 lazy loading을 사용한다.

static 블록의 특성을 기억해두면, JUnit의 @BeforeClass 어노테이션과 함께 살펴보면 공부에 도움될 것이다.

static 블록과 비슷하게 인스턴스를 위한 인스턴스 블록도 있다.

{ } 블록을 사용하게 되면, 인스턴스가 생성될 때마다, 생성자가 실행하기 전에 먼저 실행된다.

## final 키워드

final 키워드가 나타날 수 있는 곳은 딱 세 군데이다.

**클래스, 변수, 메서드**

```java
// 클래스에 final이 붙는다면 상속을 허락하지 않겠다는 의미
public final class Cat{ ... }

// 변수에 final이 붙는다면 변경 불가능한 상수
// 정적 상수는 선언 혹은 정적 생성자에 해당하는 static 블록 내부에서 초기화 가능하다.
// 객체 상수는 선언 혹은 객체 생성자 또는 인스턴스 블록에서 초기화 가능하다.
// local 상수도 존재. 선언 혹은 최초 한 번만 초기화 가능하다.
final static int staticConstMember = 1;
final int instanceConstMember = 1;

// 메서드가 final이라면 오버라이딩이 금지된다.
final void breath() { ... }
```

## instanceof 연산자

객체가 특정 클래스의 인스턴스인지 물어보는 연산자.

객체 참조 변수의 타입이 아닌 실제 객체의 타입에 의해 처리한다.

but, LSP(리스코프 치환원칙)을 위배하기에 instanceof 연산자가 보인다면 냄새나는 코드이다.

상속 관계 뿐만이 아닌, 인터페이스 구현 관계에서도 동일하게 적용된다.

## package 키워드

package는 네임스페이스(이름공간)을 만들어주는 역할.

특별히 하는 일은 없다.

Customer라는 동일 클래스를 서로 다른 팀에서 사용할 때, 이름공간을 나눠 Customer 클래스를 사용하면, 서로 완전 별개가 된다.

## interface 키워드, implements 키워드

인터페이스는 public 추상 메서드와 public 정적 상수만 가질 수 있기에 따로 메서드에 public abstract, 속성에 public static final을 붙이지 않아도 자동으로 붙여진다.

2014년 오라클에서는 빅데이터와 병렬성 지원을 강화한 자바 8 출시. 컬렉션을 강화하는 수순으로 발전할 수 밖에 없었고, 이를 위해 람다(Lambda)라고 하는 기능을 언어적으로 추가했다.

람다를 통해 변수에 로직을 저장할 수 있고, 로직을 메서드 인자로 쓸 수 있고, 로직을 메서드 반환값으로 사용할 수 있다.

자바에서 람다는 인터페이스를 기초로 두고 있다.

자바 8 이전에는 정적 상수와 객체 추상 메서드만 가질 수 있었다.

자바 8 이후부턴 객체 구상 메서드(default)와 정적 추상 메서드까지 지원

## this 키워드

this는 객체가 자기 자신을 지칭할 때 쓰는 키워드

- 지역 변수와 속성의 이름이 같은 경우 지역 변수가 우선이다.
- 동명의 객체 변수를 사용하려면 this를 접두사로 사용한다.
- 동명의 정적 변수를 사용하려면 클래스명을 접두사로 사용한다.

## super 키워드

super는 바로 위 상위 클래스의 인스턴스를 지칭하는 키워드.

super 키워드로 바로 위의 상위 클래스 인스턴스에는 접근할 수 있지만, super.super 형태로 상위의 상위 클래스의 인스턴스에는 접근이 불가하다.
